# إسناد — الإصدار الأول (النسخة الكاملة)

نظام لإدارة المعلمات والتكليفات والنصاب التدريسي، بنسخة مستقلة لكل مدرسة
(قاعدة بياناتها ومشروعها الخاص). تم تجهيز المشروع بحيث لا تحتاجين لتكرار أي
إعداد يدوي معقّد (لا SQL Editor لحسابات المستخدمين، ولا كتابة JSON) — كل ذلك
استُبدل بصفحة إعداد داخل الموقع نفسه.

---

## الفكرة العامة (مرة واحدة فقط، ثم تتكرر بسهولة لكل مدرسة)

1. **مرة واحدة الآن:** ارفعي هذا المشروع كـ "قالب" (Template) على GitHub،
   واحصلي على "رابط نشر" (Deploy Link) خاص بك.
2. **لكل مدرسة جديدة تبيعين لها:**
   - أنشئي مشروع Supabase جديد (دقيقتين).
   - الصقي محتوى `supabase/schema.sql` مرة واحدة في SQL Editor.
   - اضغطي رابط النشر نفسه من الخطوة ١ → يطلب منك 3 قيم (سترينها بالأسفل) →
     Deploy.
   - افتحي الموقع الجديد → صفحة `/setup` → عبّئي اسم المدرسة وبيانات الحسابين
     بنموذج عادي → اضغطي "تفعيل النظام".
   - انتهى. المدرسة جاهزة بموقعها الخاص.

لا حاجة لرفع ملفات يدويًا لكل مدرسة، ولا حاجة لصفحة Authentication في
Supabase، ولا حاجة لكتابة أي JSON.

---

## ١) التجهيز لمرة واحدة: رفع القالب على GitHub

1. أنشئي حسابًا على [github.com](https://github.com) إن لم يكن لديك.
2. أنشئي مستودعًا (Repository) جديدًا باسم مثلًا `isnad-template` (اجعليه
   Public)، بدون إضافة أي ملفات عند الإنشاء.
3. من صفحة المستودع الفارغ، استخدمي رابط "uploading an existing file"،
   واسحبي كل محتويات مجلد المشروع (وليس المجلد نفسه) إليه، ثم اضغطي
   **Commit changes**.

## ٢) الحصول على "رابط النشر" القابل لإعادة الاستخدام

بعد رفع المستودع، الرابط التالي هو رابط النشر الخاص بك (استبدلي
`YOUR_GITHUB_USERNAME` باسم مستخدمك في GitHub):

```
https://vercel.com/new/clone?repository-url=https://github.com/YOUR_GITHUB_USERNAME/isnad-template&project-name=isnad&env=NEXT_PUBLIC_SUPABASE_URL,NEXT_PUBLIC_SUPABASE_ANON_KEY,SUPABASE_SERVICE_ROLE_KEY&envDescription=قيم%20مشروع%20Supabase%20الخاص%20بهذه%20المدرسة
```

احفظي هذا الرابط (مثلاً في ملاحظة على جهازك) — هذا هو الزر الذي ستستخدمينه
مع **كل مدرسة جديدة**، وسيقوم Vercel تلقائيًا بعمل نسخة مستقلة جديدة من
المشروع في كل مرة.

---

## ٣) لكل مدرسة جديدة: 4 خطوات

### أ) إنشاء مشروع Supabase
1. [supabase.com](https://supabase.com) → **New Project** → اسم المدرسة ككود
   اسم المشروع.
2. من **Project Settings → API** انسخي: `Project URL` و `anon public key`
   و `service_role key` (سرّي — لا تشاركيه مع أحد).

### ب) تشغيل قاعدة البيانات
من **SQL Editor** الصقي محتوى `supabase/schema.sql` بالكامل واضغطي **Run**،
ثم `supabase/schema_v2.sql`، ثم `supabase/schema_v3.sql`، ثم
`supabase/schema_v4.sql`، ثم `supabase/schema_v5.sql` (سجل اعتماد الاحتياط).

### ج) النشر على Vercel
1. افتحي رابط النشر الذي حفظتيه في الخطوة ٢ أعلاه.
2. سجّلي دخول بحساب GitHub إن طُلب منك.
3. اختاري اسمًا للمستودع الجديد (مثلاً `isnad-madrasat-alnoor`).
4. سيطلب منك Vercel القيم الثلاث — الصقي القيم من الخطوة "أ":
   - `NEXT_PUBLIC_SUPABASE_URL`
   - `NEXT_PUBLIC_SUPABASE_ANON_KEY`
   - `SUPABASE_SERVICE_ROLE_KEY`
5. اضغطي **Deploy** وانتظري دقيقة.

### د) تفعيل المدرسة من المتصفح
1. افتحي رابط الموقع الجديد الذي أعطاكِ Vercel، وأضيفي في نهايته `/setup`.
   مثال: `https://isnad-madrasat-alnoor.vercel.app/setup`
2. عبّئي: اسم المدرسة، بيانات حسابك (مالكة النظام)، وبيانات حساب مديرة
   المدرسة — كلها حقول عادية بدون أي كود.
3. اضغطي **تفعيل النظام**.
4. سجّلي الدخول من `/login` للتأكد أن كل شيء يعمل، ثم سلّمي بيانات الدخول
   لمديرة المدرسة.

> ملاحظة أمان: صفحة `/setup` تعمل مرة واحدة فقط لكل مدرسة — بعد إنشاء أول
> حساب، ستُغلق تلقائيًا وتُظهر رسالة "تم الإعداد مسبقًا" لأي زيارة لاحقة.

## هيكل المشروع

```
src/
  app/
    setup/              صفحة الإعداد الأولي (نموذج بدل SQL/JSON اليدوي)
    login/              صفحة تسجيل الدخول
    dashboard/          لوحة التحكم (محمية بجلسة الدخول)
    api/setup/          مسار API الذي ينفّذ الإعداد فعليًا
  lib/supabase/
    admin.ts            عميل صلاحيات كاملة (service role) - للخادم فقط
    client.ts / server.ts / middleware.ts   عملاء الجلسة العادية
supabase/
  schema.sql            مخطط قاعدة البيانات + سياسات RLS (ملف واحد فقط الآن)
```

## ملاحظات مهمة

- **لا تشاركي مطلقًا** مفتاح `SUPABASE_SERVICE_ROLE_KEY` مع أي طرف خارجي أو
  تضعيه في كود يعمل بالمتصفح — يُستخدم فقط من صفحة `/setup` داخل الخادم.
- الأدوار: `owner` (مالكة النظام) ترى بيانات كل شيء في هذه النسخة، و`admin`
  (مديرة المدرسة) ترى بيانات مدرستها فقط — عبر Row Level Security مباشرة.
- **ثنائية اللغة**: زر تبديل عربي/English في الشريط العلوي يترجم القائمة
  الجانبية والشريط العلوي. جدول المناوبات في صفحة التقارير يعرض الأسماء
  والأوقات بكلا اللغتين دائمًا (بدون الحاجة لأي زر) لتسهيل قراءته على
  المعلمات غير الناطقات بالعربية. صفحات إدخال البيانات (الإعدادات،
  المعلمات، المناوبات) لا تزال بالعربية فقط، مع حقول اختيارية لإدخال
  الاسم/المكان بالإنجليزي حيث يلزم.
- **إنذار تعارض المناوبات**: عند إسناد معلمة لمناوبة، يمنع النظام تكرارها
  بنفس الوقت مع مناوبة أخرى، وينبّه (دون منع) إذا كان لديها حصة تدريس
  فعلية بنفس الوقت حسب أوقات الحصص المُدخلة في معلومات المدرسة.
- **الاحتياط**: صفحة تحت المعلمات تقترح تلقائيًا معلمات فاضيات لتغطية
  حصص أي معلمة غائبة، بمقارنة جدولها الأسبوعي مع جداول ومناوبات بقية
  المعلمات (يستثني من هو مشغول بحصة تدريس أو مناوبة متعارضة بنفس الوقت).
  يمكن **اعتماد** معلمة معيّنة بضغطة زر، فيُسجَّل ذلك تلقائيًا ويُحسب ضمن
  حدّها الأقصى للاحتياط (أسبوعي/شهري حسب ما حُدِّد عند إضافتها)، مع تنبيه
  إذا بلغت حدّها الأقصى بالفعل.
- الأقسام الفعّالة بالكامل: معلومات المدرسة، المواد،
  **المعلمات** (أنواع المناوبات، مواد متعددة، جدول أسبوعي، حدود
  الاحتياط/المناوبة، نصاب مستهدف)، **الصفوف والشعب** (عرض)، **التكليفات**
  (تُبنى تلقائيًا من جدول المعلمات)، و**النصاب** (مقارنة المستهدف بالفعلي).
